# Repository hardening on November 25, 2026

The baseline was `70cd1fb`. The review covered the runner, retry and budget logic, capability boundaries, retrieval and telemetry adapters, canonical examples, manifests, CI and prior audits. Generated paths, dependency payloads, historical audit output, and expected-output snapshots were excluded from broad source searches. The existing offline fixture suite ran without refreshing snapshots.

- Retryable failures could schedule further model calls after the runner timed out or an enforce-mode budget had been spent. A retry now checks the deadline, actual usage, and whether one additional model call would exceed the configured call limit. The result retains actual attempts and usage, with the rejected projection recorded in the budget evaluation. Observe mode still completes its configured attempts.
- Watchdog record IDs could collide when run or event IDs shared a long prefix or contained delimiters. The adapter now hashes overlong identities and unambiguously encodes compound operation identities. Start and completion retain a shared span and record ID. Batch IDs are also bounded without losing distinct long inputs.
- The RAG HTTP adapter now keeps an unsuccessful HTTP status even when the upstream body is plain text. An invalid success envelope reports an invalid response, and a missing response reports a transport error. Both runtime modes were tested against a local HTTP fixture returning a plain-text 503 and a malformed 200.
